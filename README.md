# 📝 Task Manager CLI

一个基于 Python 纯标准库开发的命令行任务管理工具，具备数据持久化与多步撤销功能。

## ✨ 核心特性
- **全功能 CRUD**：支持添加（带备注）、查看、标记完成、取消完成、删除任务。
- **多步撤销（Undo）**：采用**快照栈（Stack）**机制，支持无限步数回退任何操作。
- **数据持久化**：采用本地 JSON 格式存储，并实现**原子写入（Atomic Write）**，确保数据不丢失、不损坏。
- **分层架构**：严格遵循 `Model - Storage - Manager - CLI` 分层设计，高内聚低耦合。
- **完善的容错**：捕获文件损坏、非法指令、错误序号等异常，程序永不崩溃。

## 🛠️ 技术栈
- **语言**：Python 3.8+
- **依赖**：无第三方依赖（纯 Python 标准库）
- **数据存储**：JSON

## 🏗️ 项目架构

```text
task-manager/
├── task.py       # 数据模型层：定义 Task 结构，实现序列化/反序列化
├── storage.py    # 持久化层：负责 JSON 文件的读写与原子替换
├── manager.py    # 业务逻辑层：管理任务列表，维护撤销栈
├── main.py       # 交互层：命令行解析与用户 I/O
└── docs/         # 项目设计与需求文档
```

## 个人总结

做这个项目管理器是处于大二上学期中旬，我刚刚完成数据结构与算法和python的学习，希望做一个我实际生活用得到，又能检验所学知识的项目的背景下。诚实的说，也感慨的说，我没想到这是一件这么有意义的事情。

先说在做整个task-manager-v1的过程中我认为做的不够好的地方：

1. 在一开始过于依赖AI给出代码模版。自己不会从0~1的那一步，第一次做python项目（即使我做过C语言的项目）不知道该怎么构建项目，也没有清晰思路。
2. 对git的使用不够熟练。我原本以为自己对git的操作还比较熟悉，然而在这个过程中git的操作很多是在自己碰过很多次壁后才慢慢学会并熟悉的，比如，git代码的记忆；仓库，分支，本地的关系；如何给git配置端口以解决网络问题等等。
3. 对python库不够熟悉。python有很多很实用的库，但是我不熟悉，每当遇到一个陌生的库的时候我都要自己去查询。

那又有哪些是我认为的比较有意义的收获呢？

1. 我对项目的理解更深刻了，下一次做项目的时候或许我会先写design.md设计文档，在想项目进程安排表，在创建仓库，在构建项目结构，或许下次我会更清晰。
2. 我对git的使用熟练了很多，对于git的理解和github仓库的管理也深刻了一些，原来本地的仓库是可以切换且互相独立的，第一次推送原来要git add origin develop-v1而不是直接git push，原来给git配置端口就能解决网络问题，原来ssh密钥配置之后就这么方便了...
3. 下一次做项目说不定我对AI的依赖会更少了呢，这次是靠着AI给出框架，我自己全部学会并理解它，那下次是不是连框架都能动手自己构思呢，这应该会是一件很棒的事情。
4. 这次见识到了一些之前没应用过的代码，比如说try，装饰器，测试用例等等，项目里有很多工程化的东西我觉得是有意义的，不说对代码能力和规范化的提升，对思维也有帮助，我觉得。

这个项目还会继续迭代下去，我希望到最后能够成为一个值得上简历的项目，现在只是命令行来操作一些基本功能，他还有非常大的提升空间。

写在最后，我想v1还是有一些让我觉得比较可惜的地方，如果代码框架自己能够贡献更多就好了，如果能够涉及到更深层次的增删改查就好了，可惜这不是C语言，这是python，可惜没有用到链栈的各种使用，也没用到数据库，对于更深层次的数据结构好像没起到锻炼作用，如果对于一些命令行的使用更熟悉就好了，这样就会节省一些时间和学习成本。不过这只是v1，接下来应该会更好的，我想。
