# Task Manager v1.0设计文档

## 1. 需求（问题域）

### 1.1 目标用户与场景

面向在终端环境（后续会有版本升级）下工作的个人用户（首先是开发者自己），用于记录、跟踪、回退日常待办事项。核心场景：快速记下任务、查看当前待办、标记完成、对误操作进行回退。

### 1.2 功能需求

每条需求附验收标准（可执行、可判定）。

**FR-1 添加任务**
用户可添加一个任务，必须提供标题，可选提供备注。
- 验收：执行 `add 买牛奶` → `list` 中能看到该任务；重启程序后仍在。

**FR-2 查看任务列表**
用户可查看全部任务，每行显示序号、完成状态、标题。已完成任务用 `[√]` 标记，未完成用 `[ ]`。已完成任务仍留在列表中并占用序号。

- 验收：添加 2 个任务、完成其中 1 个 → `list` 显示 2 行，序号连续为 1、2，状态分别为 `[ ]`、`[√]`。

**FR-3 标记完成**
用户可通过列表序号将一个任务标记为已完成。已完成任务再次标记完成不产生变化。

- 验收：`done 1` → 该任务状态变为 `[√]`；再次 `done 1` → 状态不变，且不产生可撤销的新操作。

**FR-4 取消完成**
用户可通过列表序号将一个已完成任务恢复为未完成；恢复后该任务的完成时间被清空。
- 验收：任务 1 已完成 → `uncomplete 1` → 状态变回 `[ ]`；重启后该任务数据文件中完成时间为空。

**FR-5 删除任务**
用户可通过列表序号删除一个任务；删除后列表序号自动重排且保持连续。
- 验收：列表有 3 个任务，`delete 2` → 列表剩 2 行，序号为 1、2，原第 3 个任务变为序号 2。

**FR-6 撤销**
用户可回退最近一次改变任务状态的操作。可撤销的操作包括：添加、标记完成、取消完成、删除。撤销支持多步，直到没有可撤销的操作。查看列表和退出不产生可撤销记录。撤销记录仅在本次程序运行期间有效，程序退出后清空；任务列表本身重启后保留。
- 验收（多步）：连续添加 3 个任务 → 连续 `undo` 3 次 → 列表回到初始状态。
- 验收（重启后行为）：添加 1 个任务后退出程序，重新打开 → 执行 `undo` → 提示"没有可撤销的操作"，且任务列表不变。
- 验收（覆盖删除）：删除任务 2 后 `undo` → 任务 2 恢复，且回到原序号位置。
- 验收（只读不进栈）：执行 `list` 后 `undo` → 回退的是 `list` 之前的那次状态变更操作。

**FR-7 退出**
用户可主动退出程序。退出前任务列表已持久化，不丢失。
- 验收：添加任务后 `quit`，重新打开程序 → 任务仍在。

### 1.3 非目标（本期明确不做）

- 图形界面（GUI）、桌面宠物
- AI / LLM 接入、任务优先级、提醒通知
- 编辑已存在任务的标题或备注
- 撤销记录的持久化（跨程序运行保留）
- 多用户、并发访问
- 引入任何第三方依赖（纯 Python 标准库）

### 1.4 非功能约束

- **技术栈**：纯 Python 标准库，禁止第三方依赖。
- **持久化**：任务数据保存到本地 JSON 文件，重启不丢失。
- **撤销实现**：必须使用栈（Stack）数据结构。
- **模块化**：按数据模型 / 持久化 / 业务逻辑 / 交互分层，依赖方向单向。
- **容错**：必须处理非法命令、非法序号、文件不存在、文件损坏等异常，不允许程序直接崩溃。
- **交互形态**：本期为命令行（CLI），终端输出使用 ANSI 颜色区分状态。
